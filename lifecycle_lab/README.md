# Vita Lifecycle Lab

This dedicated native app qualifies autonomous installation, launching, status evaluation, cooperative exit and redeployment. Its fixed title is `VMCP00001`; accepted DevLoop builds and user applications are separate titles. The lab starts paused, draws a moving frame marker and independently checks CRC-32/ISO-HDLC against `0xa2912082` for `bytes(range(256))*16`. Variant 1 uses teal; variant 2 uses gold.

Build from the repository root with `./Build-NativeLab.ps1`, or pass `-Version 01.01 -Variant 2`. The pinned offline SDK produces `dist/native-lab/native_lab.vpk` and a source-bound `build-report.json`. Each build preserves host sanitizer/HTTP results, the native build log and package verification under `evidence/native-lab/`. The seven-entry VPK contains original artwork and the public license. The PC native-package adapter independently creates the eighth installer entry, `sce_sys/package/head.bin`; no opaque upstream header or private phone artifacts are copied.

The app reads the existing desktop administrator token from `ux0:data/vita-resident/bridge.cfg`. It must contain exactly 32 lowercase hexadecimal characters with an optional trailing LF. The token is never embedded in the executable, package, screen or report. HTTP listens on port **17868** and requires `Authorization: Bearer <token>` for every route.

- `GET /status` reports protocol 1, exact title/version/native build, positive PID, random 128-bit run identity, revision, advancing frame/time samples, paused state and deterministic self-test result.
- `POST /exit` requires exactly `expected_native_build_id`, `expected_pid`, `expected_run` and `expected_revision`, with `Content-Type: application/json`. The main thread verifies all four pins, consumes the revision and prepares the acknowledgement. Only a complete response and successful client-socket close permit main-thread cleanup and process exit. A failed send or close retains the process with the consumed revision; the old request cannot be replayed. The PC reconciles uncertain outcomes using read-only status and Resident inventory before any new operation.
- Physical `START + SELECT` exits as a local fallback. No input injection, capture, kernel helper, boot configuration or forced process destruction is used.

`resident/native_launch` permits only this title and a conservative `idle_shell_only` policy: bounded successful inventory, every occupied app resolved, zero running apps, and two successful event/overlay state samples. It repeats the guard immediately before the single platform URI call. This policy does not attest the displayed foreground or every protected system UI; its status explicitly reports both verification flags false. SDK submission, installed hashes and live app identity/frame progress remain separate evidence.

Host checks exercise the actual C core and HTTP worker with sanitizer builds, real sockets, full pin validation, malformed JSON, partial writes, response failure and socket-close failure. Native builds and package checks are complete only when their fresh build evidence passes. Hardware install, promoter acceptance, launch, concurrent Resident telemetry and repeated native redeployment require separate device qualification; no host result implies that acceptance.
